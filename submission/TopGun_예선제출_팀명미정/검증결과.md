# 제출 후보 검증 결과

검증일: 2026-08-21  
교전 제한: 규정집과 동일한 최대 120초  
상대: 운영진 제공 `AIP_BASE_target.dll` BT(혼합 시나리오에서는 제공 설정에 따라 일부 loiter 포함)  
초기조건: legacy scenario 0~7 혼합, 양측 초기 속도 이점 0, 시드별 별도 프로세스

## 최종 선택

`sac_mlp_v2_submission_a437_actor_a687_runtime`

- 알고리즘: SAC MLP actor + 저장된 pursuit guidance
- 현재 제출 계약 서버 입력 대리 평가 50시드: 7승 0패 43무, 28.5/50점(경기당 0.570점)
- 실제 격추 0회, 자체 추락 0회
- 피해 발생 7경기
- 평균 누적 상대 피해 0.0364
- 전체 최소고도 3,611.52m
- 50개 초기 기하와 trajectory hash 모두 고유

규정집의 제한시간 종료 판정처럼 양측 최종 HP를 비교해 승패를 다시 계산했습니다.
현재 계약의 1001~1030 결과는 5승 0패 25무, 17.5점이었고 1031~1050 시드는
2승 0패 18무, 11.0점이었습니다. 최초 1031~1050 실행에서 우리 기체에
40m/s 속도 이점이 남은 것을 발견해 해당 결과는 집계에서 제외하고, 양측 초기
속도가 같은 조건으로 SAC와 BT를 모두 재실행했습니다. 수정 후 50시드의 초기
속도 차는 전부 0이고 초기 기하·시드도 양 모델 간 일치합니다. 또한 1001~1010의
과거 결과가 관측/유도 분리 패치 전 trajectory인 것을 발견해 현재 코드로 두
모델 모두 재실행했습니다. 기존 저장된
`summary.json` 전체도 재감사했으며, 규정 승점이 기록된 10경기 이상
결과 중 현재 코드·현재 초기조건의 서버 입력 대리 비교에서도 이 최종 조합이 6.0점으로 가장 높았습니다.
7.5점 결과들은 공개 패킷에 없는 상태까지 쓰는 완전 상태 입력 평가이므로 제출
성능 근거에서는 분리했습니다.

SAC만 피해를 준 시드 2개, BT만 피해를 준 시드 1개였습니다. 상대를 BT로
고정한 별도 직접 비교에서도 SAC만 2경기 피해 우위를 만들었습니다.
PPO-LSTM은 recurrent 구조 자체와 무관하게 현재 체크포인트의 추락률이 높아 제외했습니다.

50개 동일 시드의 짝비교에서는 SAC 우위 7개, BT 우위 4개, 동률 39개였습니다.
따라서 SAC 선택은 유지되지만 다수가 무승부라 우위 폭은 제한적입니다. 운영진 기준 모델을 실제
BattleServer에서 양 진영으로 붙이는 검증이 최종 성능 판단에 여전히 중요합니다.

## 실행 경로 검증

- 전체 단위 테스트 110개 통과(기본 서버 주소 localhost 회귀 검사 포함)
- 직접 MLP 경로에서 Ray/RLlib 및 Gymnasium import 없음
- throttle `[-1,1] -> [0,1]` 변환은 최종 경계에서 정확히 한 번만 적용
- 음수 표적 bank 좌우 대칭화는 actor에만 적용하고 guidance는 원래 좌표계에서 합성
- Unreal XYZ(Z-up)/world velocity를 학습 NED/body velocity로 복원
- tactical25의 KCAS, ALT, yaw rate 및 WEZ 설정 전달 확인
- 실제 비행 trace yaw-rate 복원 MAE: ownship 0.05°/s, target 0.004°/s
- 실제 bundle 7,200프레임(120초×60Hz) 로컬 행동 대 Unreal CMD 최대 절대오차 0.0
- 7,200프레임 최종 재측정: Unreal 경로 평균 0.52ms, p99 1.11ms, 최대 2.48ms, 16.67ms 초과 0회
- `--validate-only` 모델/metadata 로딩 통과
- 로컬 UDP mock에서 PlaneInfo pair 1,200개에 CMD 1,200개 응답, 누락 0
- plane 0 정상 순서와 plane 1 상대 패킷 선도착 순서를 각각 1,200프레임 검증해 양 진영 모두 누락 0
- mock server가 `ClientInfo`의 팀명, RL 유형(1), 초기 plane_id(-1)를 직접 해석해 등록 계약 확인
- UDP의 지연·재정렬·중복·누락 상황에서도 동일 frame pair에만 한 번 CMD를 생성하는 테스트 통과
- 한글 팀명은 30바이트 고정 필드에서 UTF-8 문자를 중간 절단하지 않도록 검증
- 한글 팀명은 batch 코드페이지를 거치지 않고 UTF-8 `team_name.txt`에서 읽으며 29바이트 초과를 사전 거부
- 구조가 공개되지 않은 Damage/VP/StageInfo 패킷은 추측 파싱하지 않고 packet monitor에 종류·크기를 기록
- 미등록 메시지 ID와 길이가 잘린 UDP 패킷은 INVALID로 기록하고 수신을 계속하도록 검증
- 최종 UDP 왕복 재측정: plane 0 평균 1.14ms/p99 2.42ms, plane 1 역순 평균 1.16ms/p99 3.11ms
- 양 진영 모두 1,200회 처리율 838 CMD/s 이상으로 60Hz 요구량보다 충분히 높음
- 일반 `python`이 잘못된 환경을 가리키는 경우를 확인하고, 배치 파일에 AIP conda Python 자동 탐색 및 의존성 실패 처리를 적용

## 남은 실제 서버 확인 사항

이 작업 세션에서는 네이티브 BattleServer GUI가 자동 실행 세션에 창과 프로세스를 유지하지 않아 실서버 교전까지 자동화하지 못했습니다. 제출 전 `BattleServer_실연동_체크리스트.md`대로 한 번 직접 확인해야 합니다. 특히 패킷 모니터에서 고도가 양수 Z로 오고, 전진 비행 시 world velocity와 기수 방향 변환이 맞는지 확인합니다.
