아직 사용자 입력/수동 작업이 필요한 것:

1. 실제 팀명·팀번호·소속·팀원 정보를 받아 `TEAM_NAME_TO_BE_FILLED` 등 자리표시자, 폴더명, 팀 소개서와 라이브러리 안내 파일명을 바꾼다.
2. 운영진 기준 모델을 받으면 동일 PC BattleServer에서 양 진영을 바꿔 최소 3회씩 비교한다.
3. `submission\TopGun_예선제출_팀명미정\BattleServer_실연동_체크리스트.md`대로 실제 GUI 서버와 120초 실연동한다. 자동 GUI 세션에서는 서버 프로세스가 유지되지 않아 이 검증만 미완료다.
4. 패킷 모니터에서 BattleServer 좌표가 Z-up이고 velocity가 world-frame인지 확인한다. 다르면 추론 좌표 변환을 수정하고 재평가한다.
5. 수동 변경을 했다면 stage의 `__pycache__`를 제거하고 `MANIFEST_SHA256.csv`를 재생성한다. 아래 finalizer를 쓰면 캐시는 자동 제외된다.
6. 새 ZIP을 만들고 새 폴더에 압축 해제하여 52개 manifest 항목, `실행_검증.bat`, 양 진영 UDP 1,200회, 실제 서버 한 라운드를 다시 확인한다.
7. 파일 크기가 1GiB 미만인지, `명령어.txt`와 `추가필요라이브러리_[팀명].txt`가 있는지 확인한다.

팀 정보가 오면 수동 치환 대신 다음 도구를 사용한다. 원본 template은 보존하고
새 팀명 stage, 소개서/라이브러리 파일명, manifest, ZIP, SHA sidecar를 한 번에 만든다.

```powershell
C:\Users\shwsr\anaconda3\envs\aip\python.exe submission\finalize_submission_identity.py `
  --team-name "실제팀명" --team-number "실제번호" --university "소속" `
  --members "성명/역할, 성명/역할"
```

도구는 UTF-8 팀명 29바이트 제한, 제어문자, 빈 필수 신원값, Windows 파일명,
미입력 자리표시자, 파일별/ZIP 1GiB 제한을 검사하고 기존 출력은 덮어쓰지 않는다.
`__pycache__`와 `.pyc`도 자동 제외한다. 가짜 한글 팀명으로 정확히 52개 payload를
생성해 manifest, ZIP CRC, 자리표시자 제거와 `실행_검증.bat`까지 통과했다.
한글·공백을 함께 포함한 팀명과 출력 경로도 별도로 통과했다.
ZIP 날짜 태그는 실행일 기준으로 자동 생성되고 `--date-tag YYYYMMDD`로만 재정의할 수 있다.
